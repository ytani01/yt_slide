## きっかけ

「スライドを作って公開したい人が README を見て気になるところは何か」
という問いから、README を読み直した。中身は
`{title, icon, duration, narration, body}` を並べただけで、JavaScript の
文法はほぼ要らない。それなのに README の「本文の HTML を書けば」と、
`docs/User.md` の「最小の例」に出てくる
`clamp(1.15rem, 2.8cqw, 2.1rem)` で、書けない人がそこで降りる。

実際の作り方は `slides/template.js` からのコピーと差し替えなのに、それが
`docs/User.md` の中ほどにしか書いていなかった。デモは公開済み
（https://ytani01.github.io/yt_slide/）なのに README から一度も指して
おらず、`LICENSE`（MIT）も README に記載が無かった。

## 分担の振り返り

- **verifier が見つけたこと**: スマホ幅での 6px 相当。main は「文字色が
  継承されるから装飾なしでも読める」と考えて `player.html` の CSS まで
  読んだが、**`--vp-scale` で枠ごと縮む経路を見落としていた**。
  静的な読み合わせでは出ず、実際に 390x844 で開いて `getBoundingClientRect()`
  を取ったから出た。依頼に画面サイズを 2 つ名指しし、測る値を
  `font-size`・`color`・`getBoundingClientRect()` と指定したのが効いた
- **見込みとの食い違い**: 担当の構成は見込みどおり（verifier のみ）。
  ただし「文書だけの項目」という前提は外れた。文書に書いたコード例が
  実際に読めるかは挙動の確認で、結果として `player.html` を直す別項目が
  出た。料金は $2.2 で、main が 71%
- **次に同じ規模の項目をやるなら**: 文書だけの項目に見えても、**文書に
  載せるコード例を書き換えるなら実測の担当を分ける**。今回それを分けた
  から 6px が出た。逆に、main が実装前に `player.html` の CSS を読んだ
  20 分ほどは無駄が多かった。**「読めるはず」を自分で確かめようとせず、
  最初から測る担当に投げたほうが安い**（main の cache_read が 167 万で
  料金の 71% を占めた）
