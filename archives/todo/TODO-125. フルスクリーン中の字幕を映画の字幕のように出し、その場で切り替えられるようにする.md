## きっかけ

利用者から「字幕を ON にしたときは、最大化でも映画の字幕のように表示する。
最大化画面でも字幕を ON/OFF できるようにする」と頼まれた。

それまではフルスクリーン中の字幕を枠の下（`top: 100%`、暗幕の上）に出していた。
16:9 ちょうどの画面では暗幕の帯が 0px なので、字幕が画面の外に出て見えなかった。
通常画面の「字幕」ボタンも暗幕の裏で押せなかった。

## やったこと

- `player.html` の CSS で、擬似フルスクリーン中の `#subtitle-banner` を
  枠の下端（`bottom: 4%`）に重ね、文字だけを半透明の黒い帯に載せて中央寄せにした。
  波形（`#wave-container`）と見出し（新しく id を付けた `#caption-heading`）は隠す。
  文字の大きさは `clamp(14px, min(2.4vw, 4.27dvh), 44px)`（枠の幅の 2.4%）。
  帯は `pointer-events: none` で、枠のタップを塞がない
- 縦持ちは、見た目は同じまま枠の下の余白に置く（`top: calc(100% + 0.75rem)`）。
  重ねると長いナレーションでスライドの大半が隠れるため（利用者が選んだ）。
  暗幕の上にあるので `pointer-events` は戻す
- 左上の × の右隣に「字幕」と書いたボタン（`#fullscreen-caption-btn`）を置いた。
  押すと `#toggle-caption-btn` の click を呼ぶだけ。見た目は `applyCaptions()` が
  両方のボタンに反映する。最初は CC のアイコンにしたが、利用者の指示で文字にした
- `C` キーで字幕を切り替える（通常画面でも効く）。操作ガイドに足した
- 再生失敗の通知 `#audio-error-notice` は、横持ちと PC で字幕の帯と重なるので
  `z-index: 31` で上に出す
- `docs/Developer.md`（字幕バナー・擬似フルスクリーン・再生失敗の通知）と README の
  「字幕」の行を直した

## 確かめたこと

verifier が Playwright で 4 つの条件（PC 1920x1080・1280x1024、タッチ横持ち 844x390・
縦持ち 390x844）を実測した。報告は `archives/agents/TODO-125/verifier-report.md`。

- 通常表示の字幕は従来どおり枠の下
- フルスクリーン中、横持ちと PC は帯が枠の下端付近の中央、縦持ちは枠の下で画面内に収まる
- 「字幕」ボタンと `C` キーで切り替わり、2 つのボタンの `aria-pressed` と
  localStorage が一致する。検索欄にフォーカスがあるときと Ctrl+C では切り替わらない
- 横持ちで帯をタップしてもフルスクリーンを抜けず、枠のタップとして扱われる。
  縦持ちで帯をタップしても抜けない
- 再生失敗の通知は帯より上に出る
- `uv run pytest` は 35 passed

## 残ること

verifier が報告した、TODO-125 より前からの挙動（今回は直していない）:

- マウスの PC で 16:9 でない画面（1280x1024）では暗幕が無く、上下にヘッダーと
  チャプター一覧が見える。左上の × と「字幕」ボタンがヘッダーの文字に重なる
  （暗幕をマウスの PC に掛けないのは TODO-003 の判断）

## 分担の振り返り

- **reviewer** は、再生失敗の通知と帯の重なり、縦持ちでスライドの大半が隠れること、
  dvh 非対応のときの予備の値の誤り、`-webkit-backdrop-filter` の残りを見つけた。
  縦持ちの件は利用者に聞いて仕様を変えた。実装を直す指摘が 4 件あり、効いた
- **verifier** は 8 項目すべて期待どおり。新しい不具合は見つけていない。PC の
  暗幕が無い件は前からの挙動だった
- 見込みとの食い違いは verifier のモデル（Sonnet 5 と書いたが、定義の `sonnet` は
  Sonnet 5.5）だけ。次からは見込みに Sonnet 5.5 と書く
- 次に同じ規模（CSS と数行の JS、1 ファイル）をやるなら同じ組み方でよい。
  reviewer が全体の 22% で、縦持ちの仕様の穴を実装前に捕まえられたかもしれない。
  画面の向きで見え方が変わる項目は、立てるときに縦持ちの扱いも利用者に聞いておく
