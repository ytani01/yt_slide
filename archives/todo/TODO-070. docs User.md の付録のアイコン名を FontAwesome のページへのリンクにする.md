| 担当 | モデル | effort | output | cache_creation | 料金の割合 |
|------|--------|--------|--------|----------------|-----------|
| main | Opus 5 | high | 6,192 | 10,135 | 77% |
| verifier | Sonnet 5 | medium | 10,276 | 42,389 | 23% |
| 合計 |  |  | 16,468 | 52,524 | 概算 $1.3 |

- verifier は定義（`~/.claude/agents/verifier.md`）のまま `sonnet` /
  `effort: medium`

## きっかけ

TODO-069 で `docs/User.md` に付録の表を作ったが、**Markdown では
アイコンの絵が出ない**ので、名前だけ見ても何のアイコンか分からない、
という指摘。

スライドへのリンクに置き換える案は採らなかった。`docs/User.md` は
GitHub やエディタでも読まれ、HTTP で配信していないとスライドは開けない。
表そのものも `icon` に貼るコピー元として要る。画像を貼る案も、一覧を
足すたびに撮り直しになるので採らなかった。

## やったこと

付録の表の 30 件を、クラス名から `fa-` を除いたスラグで
`https://fontawesome.com/icons/<名前>?s=solid` へのリンクにした。
表の下に「名前をクリックすると実物のアイコンを見られる」の 1 行を足した。

`slides/user.js` は変えていない（スライドではリンクを踏めない）。

## 確かめたこと

**FontAwesome のサイトは、存在しないアイコンでも HTTP 200 を返す。**
立てたときには「名前が違えば 404 になるので間違いに気付ける」と書いたが、
**これは誤り**だった。`https://fontawesome.com/icons/nonexistent-xyz?s=solid`
も 200 で、`<title>Icon Not Found | Font Awesome</title>` のページが返る
（main が着手時に実測）。状態コードだけの確認は通ってしまうので、
`<title>` を見る形に変えて verifier に渡した。

verifier の確認（[報告](../agents/TODO-070/verifier-report.md)）:

- 30 件すべての `<title>` を取得。`Icon Not Found` は **0 件**。
  `fa-list-check` なら
  `List Check Filled Icon (Classic Solid) — Free SVG Download | Font Awesome`
  のようにアイコン名が入っていた（30 行の一覧が報告にある）
- URL の組み立て（`fa-` を除いたスラグ）は 30 件とも一致
- `slides/user.js` の `ICON_GROUPS` と付録の表は、用途名・クラス名・
  並び順・件数が一致。リンクになっていない名前の残りも無し
- Markdown の表の列数、コードスパンの入れ子も崩れなし

## 残ること

- verifier が `curl` を `while read` ループでバックグラウンド実行した際、
  プロセスが応答なく固着した（10 分以上 1 行も書き込まれず）。原因は
  切り分けていない。**TODO-071 として別に立てた**
- 確かめたのは 2026-09-20 時点のページ。FontAwesome 側でアイコンが
  改名・削除されればリンクは切れる

## 分担の振り返り

**verifier が見つけた食い違いは 0 件。** ただし今回の価値は食い違いの
検出ではなく、**30 件を実際に叩いたという事実**のほうにある。
`<title>` を 30 行そのまま報告に載せさせたので、「確認した」の中身が
後から辿れる。

**main が着手時に「存在しない名前」を 1 つ試したのが効いた。**
これをやらずに依頼していたら、verifier は状態コードだけ見て
「30 件とも 200、問題なし」と報告できてしまい、**誤りに気付けないまま
通っていた**。立てたときの TODO には「名前が違えば 404 になる」と
書いてあり、その思い込みのまま依頼文を書くところだった。

**見込みと食い違わなかった**（Opus 5 / high + verifier のまま）。
料金は main 77% / verifier 23% の $1.3。

次に同じ規模（外部のサイトへのリンクを足す項目）をやるなら:

- **依頼を書く前に、失敗する例を 1 件試す。** 「壊れているときに何が
  返るか」を先に見ておかないと、確認の条件を間違える。今回は
  存在しないスラグを 1 回叩いただけで、確認の軸が状態コードから
  `<title>` に変わった
- **依頼文に落とし穴を書いて渡す。** 担当が自力で気付くことを期待しない。
  今回は「状態コードだけの確認は無意味」と明記した
- verifier の規模はこのままでよい。30 件の取得と突き合わせは
  Sonnet で足りた（Haiku には渡さない。突き合わせる対象が 10 を超える）
