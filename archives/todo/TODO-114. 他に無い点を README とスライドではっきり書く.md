## きっかけ

「できること」の箇条書きが機能の列挙になっていて、どれが他に無い点なのかが
読み手に分からなかった。揃っているものが少ない 5 点を、機能の一覧とは別に
前へ出すことにした。

作業の途中で、**AI（LLM）と相性がよいことをもっと前に出す**方針が利用者から
示され、冒頭の謳い文句も差し替えることになった。

## やったこと

### 冒頭の謳い文句を差し替えた

`README.md` と `slides/readme.js` の 1枚目を、次の 1 行にした。

> AI に書かせて、そのまま再生できるナレーション付きスライド。

「AI時代の〜」のような流行語は、誰でも名乗れて中身が伝わらないため採らなかった。
差し替えに伴い、`slidesConfig.title` と、まとめのスライドの文言も合わせた。

### README に「他に無い点」の節を新設した

冒頭の 1 行はそのままに、「できること」（機能の一覧）の前へ 5 項目の節を置いた。
AI に書かせられること、依存関係が無いこと、読み上げ・字幕・自動送りが最初から
付くこと、MP4（＋`.srt`）に書き出せること、スライドがテキストファイルであること。
**それぞれ「何ができる」で止めず、「何が嬉しいか」まで書いた。**

### `docs/User.md` に「テキストで書く利点」の節を新設した

README の 5 点目の内訳を、こちらへ厚く置いた。AI に書かせられる／バージョン管理／
一括置換／自動生成／自動化／形式に閉じ込められない／エディタを選ばない、の 7 つ。
実際に動くコマンド例を各項目に添えた。

小節名は「版管理」ではなく「バージョン管理」にした（wording の推敲による）。

### `slides/readme.js` に「他に無い点」を 1枚足した

2枚目に挿入して 7枚構成にした。まとめの 3 点も、差し替えた冒頭に合わせて直した。
`duration` は `ytslide measure -n 3` の実測値。

### 読みの置換表に `AI` と `MP4` を足した

ナレーションに両方が増えたため、`player.html` の `SPEECH_RULES`（全スライド共通）へ
`MP4` → エムピーフォー、`AI` → エーアイ を追加した。複数のスライド一式で使う語なので、
スライド一式側ではなく共通の表に置いた。

`AI` は `/\bAI\b/g`（大文字のみ）にした。小文字も対象にすると `mail`・`said` の
ような語を巻き込むため。

## 分担の振り返り

**verifier が、未コミットの `slides/readme.js` を `git checkout --` で消した。**
`sed -i` で試した置換が無マッチだったのに、その後に表示された `git diff` の出力を
自分の実験結果だと誤認し、取り消すつもりで作業ツリーを HEAD へ戻した。
未ステージだったため git では復元できず、main の編集内容から作り直した。

- **各担当が何を見つけたか。** verifier は、実装より強い主張を 1 つも見つけなかった
  一方、コマンド例が実際に動くことは実測で裏付けた。`SPEECH_RULES` の追加も
  `ytslide.measure.prepare()` を直接呼んで実測しており、依頼で「読み合わせで
  済ませない」と書いた効果が出ている。wording が見つけたのは用語（「版管理」→
  「バージョン管理」）と表記の揺れだけで、主張の強さや構成には踏み込めなかった。
  Python の例が `rows` 未定義でそのままでは動かない断片だったことは、
  wording も verifier も指摘せず、main が気づいて直した
- **見込みと食い違ったのはなぜか。** 見込みの wording + verifier に対し、実施は
  main が書いて wording が推敲、verifier が 2 回という形になった。**文書の項目で
  あっても、訴求の内容そのものを決める部分は Haiku の担当に渡せない。**
  「利用者と何を訴求するか決める」工程が入る項目は、見込みの段階で main の仕事として
  数えておくべきだった
- **次に同じ規模の項目をやるなら。** 文書の内容を新しく決める項目では、
  **wording を下書きではなく推敲に置く前提で見込みを書く。**
  verifier には、**リポジトリ配下のファイルを書き換える操作を明示的に禁じる**
  （`git checkout` / `git restore` / `git stash` / `git reset` / `sed -i` / リダイレクト）。
  今回は事故のあと 2 回目の依頼でこれを書き、実際に事故は再発しなかった。
  **この禁止は依頼文ではなく `.claude/agents/verifier.md` の定義に入れるべき**で、
  毎回書くものではない（別項目として立てる）。
  事故による作り直しで main の消費が膨らんでおり（79%・$5.4）、
  防げれば $1 程度は減らせた
