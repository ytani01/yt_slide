## きっかけ

Online TTS の `onerror` と `play()` の拒否は console に警告を出すだけで、想定秒数でスライドを進めていた。見ている人には失敗が伝わらず、消音と区別しにくかった。

## やったこと

- `player.html` に通知の帯 `#audio-error-notice`（`role="status"`）を足した。文言は「音声を再生できませんでした」、ボタンは「もう一度再生」と「音声エンジンを切り替える」。状態表示は「音声エラー」にして、「消音中」「一時停止中」と分けた
- 出すのは `speakOnlineTTS()` の `onerror` と `play()` の拒否のとき。`AbortError` と、古い呼び出し（`runId` が違うもの）の拒否では出さない
- 消すのは `stopSpeech()`（スライド移動・一時停止・消音・エンジン切替・再試行がすべて通る）と、`playing`・`onended` のとき
- 「もう一度再生」は `speakCurrentNarration()`、エンジン切替は既存のボタンの click を呼ぶ（切替のロジックを複製しない）
- 出ている間も、想定秒数での自動送りと安全タイマーは変えていない
- 擬似フルスクリーンでは、縦持ちは枠の上、横持ちと PC は枠の下端に重ねる（通知を字幕と同じ枠の下に置くと画面外になるため。縦持ちで下端に重ねるとスライドの見出しを隠したので、reviewer・verifier の指摘後に縦持ちだけ上へ移した）
- `docs/User.md` に「音が出ないとき」、`docs/Developer.md` の「読み上げ」に「再生失敗の通知」を足した
- 利用者の依頼で、同じコミットに `docs/User.md` の見出しを「ユーザーズ・ガイド」に変える変更を含めた（この項目の範囲外）

## 確かめたこと

verifier が Playwright（Chromium）で実測した（`archives/agents/TODO-078/verify.mjs`、`verify-v2.mjs`）。

- 失敗の再現は 2 通り。音声要求の abort／404 と、`play()` の `NotAllowedError`。どちらも通知の表示、バッジの文言、警告の出力を確認
- 再試行で通知が消え、失敗が続くと再び出る。`Audio` の要素は 1 個のまま、再生は 1 回につき 1 つ
- エンジン切替で `voiceEngineMode` と localStorage が変わり、既存のボタンの表示と一致
- 失敗のまま待つとタイマーで次のスライドに進み、通知が消える。手動の次へ・チャプター選択でも同じ
- 正常再生・消音・一時停止・Web Speech では通知が出ない
- `play()` の拒否が遅れて届くケースで、通知もタイマーも増えない
- 1280x800、390x844（通常と擬似フルスクリーン、字幕 ON も）、844x390（擬似フルスクリーン）で通知が画面内に収まり、ボタンが最前面で押せる
- 実際の音声出力、実機、Web Speech が成功する環境での誤通知は確かめていない

`play()` を拒否しても音声ファイルが読めたときは、次のスライドまで `duration` ではなく実長＋`TTS_END_MARGIN_MS` かかる。`onloadedmetadata` が待ち時間を張り直す既存の動きで、今回の変更によるものではない。

## 見送ったもの

reviewer の検討事項のうち、次の 4 件は見送った。

- Web Speech の失敗で Online TTS に切り替わり、それも失敗したとき、「音声エンジンを切り替える」は失敗した Online TTS を再び選ぶ。どちらの方式も使えない状況で、切り替えても直らない。Web Speech 単独の失敗表示は今回の範囲外
- 失敗のあと安全タイマーで読了扱いになると、通知と「朗読完了」のバッジが待ち秒数（1〜3 秒）のあいだ同居する。次のスライドで消える
- 読了後に遅れて `error` が届くと、待ちの間だけ通知が出る。低頻度と見て未対応
- `role="status"` を `role="alert"` にする案。支援技術での読み上げは未確認

## 分担の振り返り

- **implementer が見つけたもの:** 擬似フルスクリーンで通知を字幕と同じ枠の下に置くと画面外になること。枠の下端に重ねる方式で回避した。方針（消す場所を `stopSpeech()` に集める、runId で古い拒否を弾く）は main が指定したとおりに実装され、確認スクリプトも全項目通った
- **reviewer が見つけたもの:** 通知のコメントが字幕の説明の直下に来て読み違える件（直した）、エンジン切替が同じ経路を再選択する件（見送り）、バッジの上書きなど。実測はしていないので、位置の重なりは見つけられなかった
- **verifier が見つけたもの:** 縦持ち 390x844 の擬似フルスクリーンで、下端に重ねた通知がスライドの見出しと本文を隠すこと。implementer と reviewer はどちらも見逃した。位置の直しはこれを受けて main が入れ、verifier に縦持ちだけ再測定させた
- **見込みとの差:** 担当の構成は見込みどおり。main のモデルは見込みと違ったが、Sonnet 5 で足りた。料金は main 38%、確認側 62%（reviewer 17%、verifier 25%）で、確認側が半分を超えた
- **次に同じ規模なら:** 位置や重なりの出る変更は、implementer の段階で「狭い画面（縦持ち）で通知が何を隠すか」を 1 回測らせてから reviewer に渡す。そうすれば verifier の指摘による直しと再測定（1 巡）が省ける。実装が 1 ファイル 50 行程度なら implementer を立てず main が書く選択もあるが、今回の消す場所と runId の設計は依頼に書いたので、implementer に渡したことで main の手戻りは無かった
