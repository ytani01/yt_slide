## きっかけ

**動かすのに要るのは 3 ファイル**で、「HTML 1 枚」は事実ではない。
`docs/User.md` の「他のサーバーへ持っていくとき」自身が「渡すのは次の 3 つだけ」
として `player.html` / `slides/_rules.js` / `slides/<名前>.js` を挙げている。
`player.html` は `slides/_rules.js` を無条件に読み、`prepareSpeechText()` が
その `SPEECH_RULES` を参照するため、欠けると読み上げで落ちる。

TODO-041 で `player.html` とスライドデータを分け、TODO-054 で置換表を
`_rules.js` に出した結果、分割前の `claude_memo.html` 時代の言い方だけが残った。

## やったこと

**「ファイル 3 つを置くだけで、ナレーション付きのプレゼンが動く」に変えた。**
「ビルドもインストールも不要」はそのまま使えたので残した。

| ファイル | 変更前 | 変更後 |
|----------|--------|--------|
| `README.md` 冒頭 | HTML 1 枚で、ナレーション付きのプレゼンが動く。 | ファイル 3 つを置くだけで、ナレーション付きのプレゼンが動く。 |
| `slides/readme.js` の `slidesConfig.title` | yt_slide - HTML1枚で動くナレーション付きプレゼン | yt_slide - ファイル 3 つで動くナレーション付きプレゼン |
| スライド 1 の `narration` | HTML1枚でナレーション付きの…… | 3 つのファイルを置くだけで、ナレーション付きの…… |
| スライド 1 の `h1` | HTML **1枚** で、 | ファイル **3 つ** で、 |
| まとめの `narration` | HTML 1枚でナレーション付きの…… | ファイル 3 つを置くだけで、ナレーション付きの…… |
| まとめの本文 | **HTML 1枚** でナレーション付きプレゼンが動く | **ファイル 3 つ** を置くだけで、ナレーション付きプレゼンが動く |

**`h1` だけは「を置くだけで、」を外した。** 画面で見ると、
「ファイル 3 つ を置くだけで、……」では見出しが 2 行の途中で切れて読みにくく、
利用者が短いほうを選んだ。`h1` は `render()` の中なので、ナレーションは
変わらず `duration` の測り直しも要らない。

**ナレーションが変わった 2 枚の `duration` を測り直した。**
TODO-065 で足した `-n 3`（3 回の中央値）を使った。
スライド 1 は 11 → 12、まとめは 9 → 10。

- `slides/user.js` などの「1 枚のスライド」はスライドの枚数の話なので対象外
- `README.md` と `tools/test_measure_duration.py` の `'1 枚目'` は
  サンプルの題名なので対象外

## 分担の振り返り

- **wording が見つけたもの**: 指摘は無し。6 箇所の書き換えと grep での残存確認を
  そのまま実行した。HTML の構造・クラスを保ち、グラデーションの `span` の中身
  だけを差し替えている
- **verifier が見つけたもの**: 食い違いは 0 件。ただし **スクリーンショットは
  verifier では判断できないものを出した**。「はみ出し・重なり無し」は正しいが、
  見出しが語の途中で折り返して読みにくいことは、画像を利用者に見せて初めて
  決まった
- **見込みとの食い違い**: 担当もモデルも見込みどおり。ただし `h1` の手直しが
  入ったぶん、verifier を 1 往復ぶん多く動かした
- **次に同じ規模なら**: 文言を変えて画面に出る項目では、**wording の直後に
  スクリーンショットを撮り、利用者に見せてから verifier の残りを回す**。
  今回は verifier の確認が済んでから見出しを縮めたので、撮り直しが 1 回増えた。
  撮り直しは同じ verifier に続けて頼めば計測環境を立て直さずに済む
  （実際そうして、追試は 8 回のツール呼び出しで終わった）
