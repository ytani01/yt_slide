## きっかけ

Pixel の Chrome でフルスクリーンにすると、Chrome が「上からドラッグして［戻る］を
タップ」と案内するが、ジェスチャーナビゲーションでは［戻る］ボタンが出ない。
出口は暗幕のタップと戻るジェスチャー（画面の端からのスワイプ）だけで、どちらも
画面に見えていない（利用者が実機で、この 2 つで抜けられることは確かめた）。
16:9 ちょうどの画面では暗幕が 0px になり、出口が無い（TODO-003 で対応しないと
決めた件）。

## やったこと

- `player.html` に `#fullscreen-exit-btn`（×）を足した。`#viewport-stage` の子で、
  `.is-fullscreen` のときだけ `position: fixed` で画面の左上隅に出す。
  PC・タッチ画面のどちらでも出る。押すと `setFullscreen(false)`
- 位置は最初は右上にしたが、16:9 ちょうどの画面で枠内の枚数表示
  （`SLIDE 01 / 17`）に重なるため、左上に移した（利用者が決めた）
- 背景は半透明（`bg-slate-900/85`）。PC では暗幕が無く、レターボックスに
  裏のページのロゴが映って × と重なるので、透けすぎないようにした
- 操作ガイドの文言を、× と Android の［戻る］操作を案内する形に書き換えた
- `docs/Developer.md` の「擬似フルスクリーン」に説明と図の入口を足し、
  「暗幕が無いと抜けられない」という記述を今の状態に合わせた。
  `player.html` の TODO-003 のコメントも同様

## 確かめたこと

verifier が Playwright の headless chromium で 1920x1080・1280x800（マウス）、
844x390・390x844（タッチ）を実測した（`archives/agents/TODO-123/verify.py`）。
通常表示で非表示、フルスクリーンで左上 (12,12)-(52,52) に出て `elementFromPoint` が
× を返すこと、枚数表示と重ならないこと、押すと通常表示に戻り再生状態が
変わらないこと、操作ガイドの文言、コンソールエラー 0 件が、すべて期待どおりだった。
背景を濃くしたあと main が同じスクリプトを流し直し、結果は変わらなかった。

## 残ること

- 実機（Pixel の Chrome など）では × を確かめていない
- PC のフルスクリーンでは、レターボックスに裏のページが映る（以前から。
  PC に暗幕を敷かないのは TODO-003 の判断）

## 分担の振り返り

- reviewer は、16:9 ちょうどの画面で × が枚数表示に重なることと、
  「暗幕が無いと抜けられない」という記述が 2 か所で古くなったことを見つけた。
  前者は位置を左上に移し、後者は書き換えた
- verifier は、1280x800 で × が裏のページのロゴと重なって見えることを挙げた。
  背景を濃くして対処した
- 見込みどおりの編成で、食い違いは無かった
- 次に同じ規模（1 ファイルに要素 1 つと CSS・JS 数行）なら同じ編成でよい。
  reviewer に Playwright で複数の画面比率を測らせたのが、重なりを拾うのに効いた。
  位置を変えたあとは reviewer を回し直さず verifier の実測に任せたが、
  変更が CSS の 1 行だったので足りた
