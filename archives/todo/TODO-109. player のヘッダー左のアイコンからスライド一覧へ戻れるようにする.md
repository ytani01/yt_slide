# TODO-109. player のヘッダー左のアイコンからスライド一覧へ戻れるようにする

|      | main | 担当 |
|------|------|------|
| 見込み | Opus 5 / effort high | verifier |
| 実施 | Opus 5 / effort high | verifier |

| 担当 | モデル | effort | output | cache_creation | 料金の割合 |
|------|--------|--------|--------|----------------|-----------|
| main | Opus 5 | high | 3,397 | 14,893 | 65% |
| verifier | Sonnet 5 | medium | 8,209 | 32,223 | 35% |
| 合計 |  |  | 11,606 | 47,116 | 概算 $0.7 |

- verifier は定義（`~/.claude/agents/verifier.md`）のまま sonnet / medium

## きっかけ

`player.html` を開くと、スライド一覧（`index.html`）へ戻る手段が画面に
無かった。ブラウザの戻るしか無く、URL を直接開いたときは戻れない。

## やったこと

`player.html` の 1 箇所だけを変えた。ヘッダー左のアイコンの `<div>` を
`<a href="index.html">` にした。クラスは元のまま移し、`flex-shrink-0` と
`title` / `aria-label`「スライド一覧へ戻る」を足した。

タイトルとファイル名は当たり判定に入れない（利用者と相談して決めた）。

## 確かめたこと

verifier が Playwright（chromium）で実測した。報告は
[archives/agents/TODO-109/verifier-report.md](../agents/TODO-109/verifier-report.md)。

`player.html`（既定）と `?slides=user` を 1280x800 と 375x667 の 4 通りで
開き、いずれも次を確認した。

- アイコンをクリックすると `index.html` に遷移する
- アイコンの大きさは 32x32 のまま
- 横スクロールは出ない（`scrollWidth` == `clientWidth`）
- コンソールエラーは無し
- 再生/一時停止のスペースキーは従来どおり効く

## 残ること

375x667 でアイコンに Tab フォーカスを当ててスペースを押すと、ページが
367px スクロールする（1280x800 では起きない）。`player.html` の keydown
ハンドラが元から `a` を除外しているため、ブラウザ標準のスクロールが
そのまま働く。リンクはスペースでは押せない（Enter のみ）ので、他のサイトと
同じ挙動になっただけと判断し、直さなかった。

## 分担の振り返り

- verifier は、遷移・大きさ・横スクロール・コンソールの 4 点では食い違いを
  見つけなかった。見つけたのは、依頼文に足したキーボード操作の確認だけ。
  `<div>` を `<a>` にするとフォーカスの対象が増えるという、差分を読むだけ
  では気付きにくいところだったので、この確認項目を足した分は効いた
- 見込みと食い違いは無い。$0.7 で、うち main が 65%
- 次に同じ規模（HTML の 1 箇所を書き換えるだけ）なら、同じ組み方でよい。
  要素の種類が変わる変更では、キーボード操作とフォーカスの確認を
  依頼文に必ず入れる
