# TODO-088 の分担

| 担当 | 役割 |
|------|------|
| main | 実測の依頼、文言の案づくり、文書とスライドの修正、`duration` の測り直し |
| verifier | `file://` での実測、直した文言の再現確認（3 回） |

## この分担にした理由

**実測の前には文言の案を出せない**項目だった。「簡易サーバーが要る」と書くか
どうかが、`file://` で音声が鳴るかどうかで決まるため。だから最初に
verifier へ実測だけを渡し、値が出てから利用者と文言を決めた。

確認を分けたのは、**書いた本人は「同じ主張を全部直した」で済ませてしまう**から。
実際、main の洗い出しは 4 箇所を漏らしており、うち 2 箇所は verifier の
2 回目の確認で見つかった。

implementer は立てなかった。文言の差し替えだけで、分けて渡すほどの実装が
無かった（見込みでは implementer + verifier としていた）。

reviewer も立てていない。分岐や条件式は変えておらず、「良いか」を問う対象が
無い。

## 依頼の条件

- 計測の手段まで指定した（Playwright / headless Chromium / 1280x800、
  playwright を借りる `NODE_PATH` まで）。書かないと静的な読み合わせで返る
- **`file://` と `http://` を必ず並べて測らせた。** ヘッドレスに音声デバイスが
  無いことと、`file://` の制約を混同させないため。実際 Web Speech API は
  両方で失敗し、「`file://` 固有ではない」という切り分けだけが残った
- 2 回目以降は**同じ担当に続けて頼んだ**。計測環境の組み直しを避けるため
- 原因の切り分けと境界線上の判断はさせず、報告だけにさせた
